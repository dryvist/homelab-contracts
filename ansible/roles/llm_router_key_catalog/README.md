# llm_router_key_catalog

Single-source catalog for LiteLLM virtual key names generated by
`ansible-proxmox-apps` and consumed by `ansible-proxmox-ai`.

## What it loads

The role reads `files/router-key-catalog.json` and publishes:

- `llm_router_key_catalog_facts.llm_router_key_catalog_source` — the benchmark
  field and the program key runner, purpose, and target dimensions.
- `llm_router_key_catalog_facts.program_key_definitions` — each program alias
  and its matching OpenBao field.
- `llm_router_key_catalog_facts.program_key_catalog` — all program fields
  grouped under the `benchmark` app path.
- `llm_router_key_catalog_facts.openbao_router_key_catalog` — the benchmark
  key plus program fields grouped under `benchmark` for OpenBao seeding.

The `targets` array is the shared key-field contract. The router filters it
against the live model registry and reachable fallback targets. Consumer
tests assert that every reachable target is present in the shared catalog.

## Usage

Include this role before a consumer that reads its facts, or declare it as a
role dependency:

```yaml
roles:
  - role: dryvist.homelab.llm_router_key_catalog
  - role: openbao
```

The OpenBao generator stores the fields under `secret/apps/benchmark`; router
consumers read those fields through `bao_apps_secrets`.
